## まず試す（Firebase なし）

`config.js` の `USE_FIREBASE` が `false` のままだと **テストモード** で動きます。同じブラウザのタブ同士でだけ遊べるので、動作確認用です。

`index.html` をダブルクリックで開き、同じブラウザでタブを3つ以上開けば（2つ目以降は表示されたルームコードで参加）、1人で通しプレイできます。

## 本番の準備（スマホで遊ぶ）

### 1. Firebase をオンにする

`config.js` には、穴〇め早打ちで使っていた Firebase（tetris-god）の設定がすでに入っています。
いちばん上の行を `true` に変えるだけです。

```js
const USE_FIREBASE = true;
```

別のプロジェクトを使うときは、`FIREBASE_SETTINGS` の中身を Firebase コンソール（歯車 →「プロジェクトの設定」→「マイアプリ」）からコピーした設定に置き換えます。データは `party/` の下に保存されるので、テトリス神。などと混ざりません。

### 2. データベースのルールを追加する

**ここを忘れると、Firebase をオンにしても「読み込み中」や接続エラーのままになります。**

Firebase コンソール → Realtime Database →「ルール」に、`party` の部分を足して「公開」を押します。テトリス神。や穴〇め早打ち（`anaume`）のルールがすでにあれば、消さずに並べて書きます。

```json
{
  "rules": {
    "party": {
      "rooms": {
        "$code": { ".read": true, ".write": true }
      }
    }
  }
}
```

### 3. GitHub Pages に公開する

1. `party` フォルダの中身を GitHub のリポジトリに置く（新しいリポジトリでも、gamecreate54 の中のフォルダでもOK）
2. リポジトリの「Settings」→「Pages」で公開
3. 表示されたURLをスマホで開けば完成

## 遊び方の流れ

ホストが「部屋を作る」→ 3桁のルームコードか「招待する」のリンクでみんなを呼ぶ → ロビーでゲームを選んで開始。

**ワードウルフ**

1. ホストがモード・人狼の人数・周回数・ジャンルを決めて開始
2. 自分のお題を確認 → 通話で順番に発言（本人が「話し終わった」をタップ）
3. 投票 → 同票なら決選投票 → それでも同票ならランダム
4. 人狼が吊られたら逆転チャンス。回答をホストが ○× 判定

**穴〇め早打ち**

1. ロビーで出題者を選ぶ（ホスト／交代制＝1問ごとに順番に交代／特定の人を指名）。問題の合間にホストが変えることもできる
2. 出題者がお題を入力。〇はキーボードではなく〇ボタンで入れる。〇はいくつでもOK
3. 〇の数だけ正解欄が出るので、それぞれに正解を入力（1つの〇に2文字以上もOK、別解は「/」区切り）して出題
4. 答える人は〇に入る文字を前から順につなげて打って送信（例：〇ン〇ン→「パパ」）。みんなの入力中の文字がリアルタイムで見える
5. 最初に正解した人に1ポイント。別解は出題者が回答をタップして手動で正解にできる

**うんち爆弾**

1. 最初に💩を持つ人がランダムで決まり、3秒後にスタート
2. 💩が来たら3回タップしてふいてから、押しつける相手をタップ（渡してきた人には返せない）
3. 爆発の時間はだれにも分からない。残りが少なくなると💩が震えだす
4. 爆発したとき持っていた人に💩+1。全ラウンド後、一番少ない人の勝ち

**以心伝心**

1. お題に、みんなが書きそうな答えを入力（全員そろうまで他の人には見えない）
2. 同じ答えを書いた人1人につき1点。カタカナ・ひらがなは自動で同じ扱い
3. 「林檎」と「りんご」のような表記ゆれは、ホストが答えを2つタップしてまとめられる

**かぶったらダメ**

1. 全員が同時に数字を選ぶ（みんながそろうまで変更OK）
2. だれともかぶらなかった人は、その数字がそのまま得点。かぶったら0点

**ぴったりストップ**

1. 全員いっせいにスタート。タイマーは最初の数秒しか見えない
2. 目標の秒数ぴったりだと思ったら STOP。近い順に高得点、±0.05秒以内はボーナス+3

**お絵かきクイズ**

1. 描く人が順番に回ってくる。描く人だけにお題が見える（文字を書くのは禁止）
2. ほかの人は答えを何回でも入力。早く当てた順に3→2→1点、描いた人も当ててもらえた人数ぶん+1点
3. 全員が当てるか時間切れで正解発表。描く人は「パス」、ホストは「この回を終わらせる」もできる

**数字ならべ（協力）**

1. レベルの数だけ1〜100のカードが配られる（自分の分しか見えない）
2. 数字は言わずに、テーマ（例：こわいもの）に沿ったヒントで伝え合う。ヒントは画面に書いても出せる
3. 一番小さいと思う人から「出す」。自分より小さいカードを持った人がいたらライフ−1
4. 目標のレベルまでクリアしたらみんなの勝ち

**連打バトル**

1. 3秒のカウントダウンのあと、制限時間いっぱい連打。みんなの回数はバーで見える
2. ラウンドごとに「ふつう → 交互連打 → 逃げるボタン → ピタッと止める（目標回数ちょうど）」とルールが変わる

**この中でいちばん…**

1. お題（例：一番遅刻しそうなのは？）に、自分以外のだれかへこっそり投票
2. 一番票を集めた人に投票していたら+1点。選ばれた人には称号が付き、最後に称号コレクションを発表

**しりとりサバイバル**

1. 順番に、制限時間内にひらがな・カタカナでしりとりの言葉を入力
2. 時間切れ・「ん」で終わる・もう出た言葉はライフ−1。ライフがなくなったら脱落、最後の1人が勝ち
3. 存在しない言葉は、ホストが「ダウト」で取り消せる（言った人のライフ−1）

**ウソつきトーク**

1. 各自が会話でつくウソを1〜3個書く（自分のスマホにだけ保存され、答え合わせまで誰にも送られない）
2. 通話でふつうに会話。困ったら話題ボタン（全員の画面に同じ話題）
3. 「今のウソでしょ」と思ったら嘘コール → 相手を選ぶ → 言われた本人が正直に判定
4. ホストが会話を終えたら答え合わせ。バレずに言い切ったウソは+1
5. 得点：ウソがバレなかった +1 / バレた −1 / 嘘コール成功 +2 / 失敗 −2

**笑ったら負け**

1. ロビーで「勝ち残り人数」と「ワード制限時間」を決めて開始
2. 笑ったら自分で「笑った」ボタンを2回押して脱落
3. 相手1人につき1回、単語を送りつけられる。送られた人の画面にだけ単語が出るので、制限時間内に会話で言って「言った！」を押す。言えなければ脱落
4. ホストは、回線落ちや放置の人のカードをタップすると強制脱落にできる
5. 勝ち残り人数まで減ったら終了

ゲームを終えるときは、ホストが右上の「ロビーへ」を押します（得点はリセット）。

ホストが落ちたときは、他の人の画面に「自分がホストになる」ボタンが出ます。同じタブで再読み込みしても席に戻れます。

## ワードウルフのお題を増やす

`games/wordwolf/topics.js` の `pairs` に `['A', 'B']` を足すだけです。ジャンルを増やすときはブロックごと追加します。

## ゲームを追加する

1. `games/<ゲーム名>/game.js` を作る（`games/wordwolf/game.js` をコピーして書き換えるのが早いです）。中で `window.Party.register({ ... })` を呼んで自分を登録します
2. `index.html` の「ゲーム（追加するときはここに足す）」の下に1行足す。見た目のファイルを作ったときは、上の「ゲームごとの見た目」にも1行足す

```html
<!-- ===== ゲーム（追加するときはここに足す） ===== -->
<script src="games/wordwolf/topics.js"></script>
<script src="games/wordwolf/game.js"></script>
<script src="games/anaume/game.js"></script>
<script src="games/usotsuki/topics.js"></script>
<script src="games/usotsuki/game.js"></script>
<script src="games/waraimake/game.js"></script>
<script src="games/newgame/game.js"></script>
```

ゲームのファイルに必要なもの：

| 名前 | 役割 |
| --- | --- |
| `id` `name` `icon` `description` | ゲーム一覧に出る情報 |
| `defaultSettings()` | 設定の初期値 |
| `validate(ctx)` | 開始できないときの理由（OKなら `null`） |
| `renderSettings(ctx, { editable, set })` | ロビーの設定画面 |
| `start(ctx)` | 開始時の状態を返す（ホストの端末で動く） |
| `handle(ctx, action)` | 操作を受けて新しい状態を返す（ホストの端末で動く） |
| `render(ctx)` | 今のフェーズの画面を返す（全員の端末で動く） |

`start` と `handle` が返すもの：

- `game`：全員に見える状態
- `private`：ホストだけが読む情報（正解など）
- `secrets`：`{ プレイヤーID: { ... } }` の形で、各自が自分の分だけ読む情報
- `memory`：部屋に残る情報（次のゲームでも使う）

画面からは `ctx.send('操作名', { ... })` で操作を送ります。届いた操作には、サーバーの時刻 `ts` が付きます（早押しの順番判定に使えます）。

短いゲームなら `games/kaburi/game.js`（かぶったらダメ）が一番シンプルなお手本です。得点表や最終結果の画面は `window.Party.kit` の部品を使えます。

時間切れのように「時間がたったら何かが起きる」ゲームは、`tick(ctx)` を書いておくと、ホストの端末で0.25秒ごとに呼ばれます（変化がなければ `null` を返す）。

入力中の文字のように頻繁に変わるものは、ホストを通さず `ctx.setLive(値)` で自分の欄に直接書き、`ctx.live[プレイヤーID]` でみんなの分を読めます。

## 注意

- 元の単独版（穴〇め早打ち・ウソつきトーク・笑ったら負け）は `anaume` などの別の場所にデータを保存していました。パーティールームは `party` の下にまとめて保存するので、ルールに `party` の追加が必要です（元のルールは残しておいて大丈夫です）。
- お題は各自の分だけ読み込む作りですが、ルールで読み取りを制限していないので、詳しい人なら開発者ツールで他人のお題を見られます。身内で遊ぶ前提の v1.0 の仕様です。
